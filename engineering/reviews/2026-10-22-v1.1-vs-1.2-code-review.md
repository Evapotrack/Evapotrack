# Code review: live v1.1 (`main`) vs planned 1.2 (`release/1.2`), 2026-10-22

- **Scope:** app code and tests (`Evapotrack/`, `EvapotrackDevTests/`, project file). About +3,300/−775 app lines in 55 files, plus about 2,700 test lines.
- **Method:** automated review (high effort), then each finding checked by hand against the code, how it's used and what depends on it.
- **Not run:** `release/1.2` has never been compiled or run, so every finding comes from reading the code.

## Verdicts

| # | Finding | Checked in context | Real-world impact | Verdict |
|---|---|---|---|---|
| 1 | Insights text calls the engine's *estimate* "retained": "(1.00 L retained)", "needs at least 1.00 L" | Real. With one measured watering, a later no-runoff raise or the capacity cap changes the estimate, but the sentence still says "retained". A capacity note does appear next to it when capped | A grower sees a number that doesn't match their log. That undermines trust in Next, which is the app's core | **Fix in 1.2.** Reword (e.g. "expected retention X"), or show the measured value. EN/ES strings only |
| 2 | 7 test setups create `ModelContext(container)` without keeping the container | Real. The v1.1 tests kept the container (`container.mainContext`). Whether the context keeps the container alive on iOS 17 is uncertain | Tests could crash or flake on the first Xcode run, hiding real results. No effect on users | **Fix in 1.2 (Phase 4).** Keep the container in the test (mechanical, about 7 lines) |
| 3 | After saving a log with a photo, the form still points at the moved photo files for the 1 s "Saved" overlay (taps pass through it) | Real, but the window is 1 s and the sheet then closes itself | A tap on the thumbnail in that second shows "Photo unavailable". Cosmetic, nothing is lost | **Fix in 1.2 (cheap):** clear the photo state on save, or block taps under the overlay |
| 4 | Number parser removes spaces and apostrophes anywhere: "1 5" → 15 | Real. Every number field uses the decimal pad, which has no space key, so it only happens via paste, dictation or an iPad hardware keyboard | Rare, but it silently saves a 10× wrong volume | **Fix in 1.2:** accept spaces only as thousands groups (the same check already used for "." and ",") |
| 5 | Export dates use the device language; new photo sentence is English-only | Not a regression: the v1.1 export is English-only with device-language dates too, and the format is locked by tests | None new | **Defer.** Localizing the whole export is a later item (LOC-3) |
| 6 | Two new places round numbers with `String(format:)` instead of `DisplayFormatter` | The shared formatter also uses `String(format:)`, so the output is identical | None today | **Optional tidy-up** in Phase 5 |
| 7 | Dashboard recomputes Next on every redraw | True, but it's milliseconds even for hundreds of logs per plant | None noticeable | **Defer** |
| 8 | Reduce Motion code copied in 3 places | True | None | **Optional tidy-up** |
| 9 | Goal range defined in 3 places (model clamp 0.1–99.9, validation and engine 5–50) | The model clamp is v1.1's divide-by-zero guard. Plants from v1.1 keep their goal, and the engine clamps it to 5–50 with a visible note, as designed (ALG-4) | None. Behaves as designed | **Keep.** Add a comment that the model clamp is a safety guard |
| 10 | `save()` re-parses values `validate()` already parsed; "drift" example (whitespace) | The example is wrong: `NumericInput.parse` trims whitespace itself, so both paths agree | None | **Optional tidy-up**, no behavior change |

## Recommendation
- **Fix 1–4 on `release/1.2` before the first build**, alongside Phase 4. They're small, isolated, and include tests and EN/ES strings.
- **Defer 5 and 7. Treat 6, 8 and 10 as optional Phase 5 tidy-ups. Keep 9** with a comment.
- **None of these affects the live v1.1** or anyone's stored data.
